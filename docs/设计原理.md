# 设计原理

## 项目定位

Jellyfin 远程播放加速器不是 CDN，也不是传统意义上的边缘缓存系统。

它的目标是解决家庭 NAS 通过公网访问时，由于家庭宽带上行能力不足或不稳定导致的远程播放问题。

核心思路：

1. VPS 作为公网访问入口；
2. 家庭 NAS 主动连接 VPS 建立反向隧道；
3. VPS 根据播放进度提前获取 Jellyfin HLS 分片；
4. 播放器访问 VPS 缓存，减少实时家庭上传压力。

## 数据流程

```
远程播放器
      |
      v
VPS Nginx
      |
      +---- 播放请求
      |
      +---- 预取 Worker
                |
                v
          家庭 NAS Jellyfin
```

## HLS 分片预取

Jellyfin HLS 播放会产生连续分片：

```
001.ts
002.ts
003.ts
...
```

播放器播放当前分片时，Worker 提前获取后续分片。

## 转码生命周期

系统按照以下状态管理：

```
新播放
  |
  v
WARMUP
  |
  v
LIVE 预取
  |
  v
DRAIN 滚动同步到 current+500
  |
  v
HOLD 保留当前窗口
```

## Session 管理

系统监控：

- 播放路径 prefix；
- Jellyfin 转码 hash；
- 分片生成进度。

当 hash 变化时，认为 Jellyfin 创建了新的转码会话，需要重新建立缓存上下文，避免不同转码任务混用。
