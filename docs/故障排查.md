# 故障排查

## 播放卡顿分析顺序

### 1. 查看播放缓存命中

检查 Nginx 日志：

```
cache=HIT
```

表示 VPS 已有缓存。

```
cache=MISS
```

表示需要从家庭 NAS 获取。

### 2. 查看 Worker 状态

关注：

- 当前 session；
- hash 是否变化；
- 当前预取位置；
- DRAIN 是否完成。

### 3. Hash 变化

Jellyfin 转码过程中可能产生新的 hash。

如果发现：

```
旧 hash
   |
新 hash
```

需要重新建立 session 上下文。

### 4. 常见问题

#### 播放 MISS

检查：

- 预取是否运行；
- 播放 URI 与预取 URI 是否一致；
- cache key 是否一致。

#### 转码结束后仍卡

检查：

- 是否进入 DRAIN；
- 是否完成剩余分片同步；
- 是否存在根据 `NAS inactive` 每分钟清空缓存的旧定时任务；
- nginx error log 是否出现缓存文件 `chmod/unlink` 不存在。

`NAS inactive` 只代表转码完成。此时 worker 正需要读取已生成的分片完成 DRAIN，不能
把它当成播放器关闭信号。

#### 长时间暂停

暂停状态不应该立即删除缓存。

精确删除需要结合 Jellyfin PlaybackStop 事件。
