# Jellyfin 远程播放加速器

一个面向家庭 Jellyfin 用户的远程播放优化系统。

本项目通过 VPS 公网节点、反向隧道和 HLS 分片预取机制，将家庭 NAS 生成的视频分片提前同步到 VPS，减少家庭宽带公网持续上传压力，提高 Jellyfin 远程播放的稳定性。

> 本项目不是 CDN，也不是传统边缘缓存系统。它的目标是优化家庭 NAS 到公网用户之间的远程播放链路。

---

# 为什么需要这个项目？

很多家庭宽带存在类似情况：

- 下载速度正常；
- 局域网访问 NAS 正常；
- Speedtest 测试结果正常；
- 但是公网远程访问服务时，上行吞吐不稳定。

对于 Jellyfin 远程播放，视频数据需要持续从家庭网络上传：

```
远程播放器
      |
      |
公网
      |
      |
家庭宽带上传
      |
      |
NAS + Jellyfin
```

当实际公网可用上传能力低于视频码率需求时，会出现：

- 起播慢；
- 快进等待；
- 播放缓冲；
- 长时间观看不稳定。

本项目不是提升家庭宽带速度，而是改变数据传输方式。

---

# 核心思路

使用 VPS 作为公网访问节点：

```
远程播放器
      |
      v
VPS 公网节点
      |
      v
家庭 NAS
```

VPS 负责：

1. 提供公网访问入口；
2. 缓存 Jellyfin HLS 视频分片；
3. 根据播放位置提前获取后续分片；
4. 在 NAS 转码完成后继续同步已经生成的分片。

最终效果：

```
家庭 NAS
   |
   | 提前同步
   v
VPS
   |
   | 稳定提供播放
   v
远程用户
```

---

# 为什么使用 TCP 443 反向隧道？

本项目来自实际家庭宽带远程播放优化场景。

在部分上海电信家庭宽带环境中测试发现：

- 普通公网访问路径上传性能下降明显；
- TCP 443 加密隧道连接能够获得更稳定的上传表现。

因此采用：

```
家庭 NAS
    |
    | 反向隧道
    | TCP 443
    |
    v
VPS
```

原因：

- 实测环境中该路径上传表现更稳定；
- 家庭端主动连接 VPS，避免公网入站困难；
- 减少 NAT、防火墙和家庭网络环境影响。

注意：

- 443 并不是绕过认证或安全机制；
- 不保证所有地区、运营商和时间均有效；
- 使用前应自行测试网络路径。

# 核心功能

## HLS 分片预取

Jellyfin 播放通常使用 HLS：

```
movie/
 ├──001.ts
 ├──002.ts
 ├──003.ts
 └──...
```

系统根据当前播放位置提前获取后续分片：

```
当前播放:
100.ts

后台同步:
101.ts
102.ts
103.ts
...
```

降低网络波动对播放的影响。

---

## NAS 转码完成后继续同步

普通缓存：

```
NAS 转码结束
      |
      v
停止
```

本项目：

```
NAS 转码结束
      |
      v
继续同步已生成 HLS 分片
      |
      v
VPS 缓存完成
```

充分利用 NAS 已生成的视频分片。

---

## 转码 Session 管理

Jellyfin 转码过程中可能出现：

- hash 变化；
- 新转码任务；
- ffmpeg 生命周期变化。

系统跟踪：

```
播放路径
+
转码 hash
+
生成进度
```

避免不同播放任务之间缓存状态混乱。

---

## 播放状态管理

设计状态：

```
PLAYING
   |
PAUSED
   |
CLOSED
```

目标：

- 播放中：持续优化；
- 暂停：保留已有缓存；
- 关闭：释放资源。

# 系统架构

```
远程播放器
      |
      v
VPS Nginx
      |
      +---- HLS 缓存
      |
      +---- 预取 Worker
      |
      v
反向隧道 TCP 443
      |
      v
家庭 NAS
      |
      v
Jellyfin
```

# 适用场景

适合：

- 家庭 NAS；
- Jellyfin 远程播放；
- 家庭宽带公网上传不足；
- 希望提高远程观看稳定性。

不适合：

- 商业 CDN；
- 大规模多人分发；
- 绕过访问控制。
