# Jellyfin 远程播放加速器

一个面向家庭 Jellyfin 用户的远程播放优化系统。

本项目通过 VPS 公网节点、反向隧道和 HLS 分片预取机制，将家庭 NAS 生成的视频分片提前同步到 VPS，减少家庭宽带公网上传压力，提高 Jellyfin 远程播放的稳定性。

---

## 背景

很多家庭宽带存在这样的情况：

- 下载速度正常；
- 局域网访问 NAS 正常；
- Speedtest 测试结果正常；
- 但是公网远程访问服务时，上行吞吐不稳定。

对于 Jellyfin 远程播放，高清视频需要持续从家庭网络上传：

```
远程播放器
    |
    |
家庭宽带公网上传
    |
    |
家庭 NAS + Jellyfin
```

当实际公网上传能力低于视频码率需求时，会出现：

- 起播慢；
- 快进等待；
- 播放过程中缓冲；
- 长时间观看不稳定。

本项目的目标不是提高家庭宽带本身的上传速度，而是优化远程播放的数据传输路径。

---

# 解决思路

通过 VPS 作为公网访问节点：

```
远程播放器
      |
      v
VPS 公网节点
      |
      v
家庭 NAS
```

VPS 负责：

1. 接收远程 Jellyfin 播放请求；
2. 缓存 HLS 视频分片；
3. 根据播放进度主动预取后续分片；
4. 在家庭端转码完成后继续同步已经生成的视频分片。

这样可以把家庭宽带持续上传压力转换为提前同步。

---

# 为什么使用 TCP 443 反向隧道？

本项目来源于实际家庭宽带远程播放优化场景。

在部分上海电信家庭宽带环境中测试发现：

- 普通公网访问路径上传性能明显下降；
- TCP 443 加密隧道连接能够获得更稳定的上传表现。

因此采用：

```
家庭 NAS
   |
   | 反向隧道
   | TCP 443
   |
   v
VPS
```

使用 443 的原因：

- 测试环境中该路径上传表现更稳定；
- 家庭端主动建立连接，避免公网入站困难；
- 减少 NAT、防火墙和家庭网络环境带来的影响。

注意：

- 这不是绕过认证或安全控制的方法；
- 不保证所有运营商、地区和时间都有效；
- 使用前建议自行测试不同端口和路径。

# 核心功能

## 1. HLS 分片预取

Jellyfin 远程播放通常使用 HLS 分片：

```
movie/
 ├──001.ts
 ├──002.ts
 ├──003.ts
 └──...
```

播放器播放当前分片时，系统提前获取后续分片：

```
当前播放:
100.ts

后台预取:
101.ts
102.ts
103.ts
...
```

减少网络波动对播放的影响。

---

## 2. 转码完成后继续同步

普通缓存方案：

```
NAS 转码结束
      |
      v
停止缓存
```

本项目：

```
NAS 转码结束
      |
      v
继续同步已生成 HLS 分片
      |
      v
VPS 缓存完成
```

充分利用 VPS 作为远程播放中转节点。

---

## 3. 转码 Session 管理

Jellyfin 转码过程中可能发生：

- hash 变化；
- 新转码任务启动；
- ffmpeg 生命周期变化。

系统监控：

```
播放路径
+
转码 hash
+
生成进度
```

避免不同转码任务之间缓存状态混乱。

---

## 4. 播放状态管理

设计状态：

```
PLAYING
   |
PAUSED
   |
CLOSED
```

目标：

- 播放中：持续优化；
- 暂停：保留已有缓存；
- 关闭：释放资源。

# 系统架构

```
远程播放器
      |
      v
VPS Nginx
      |
      +---- HLS 缓存
      |
      +---- 预取 Worker
      |
      v
反向隧道 TCP 443
      |
      v
家庭 NAS
      |
      v
Jellyfin
```

# 适用场景

适合：

- 家庭 NAS；
- Jellyfin 远程播放；
- 家庭宽带公网上传不足；
- 需要长期稳定观看。

不适合：

- 商业 CDN；
- 大规模多人分发；
- 绕过访问控制。
